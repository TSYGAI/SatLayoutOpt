# SatLayoutOpt

SatLayoutOpt 是一个面向卫星舱段配载方案设计与比较的三维工作台。项目以 STEP 模型为几何源，串联模型管理、安装约束设置、舱段配置、布局优化和人工微调，支持三维预览、历史方案管理及安装参数导出。

## 项目简介

卫星配载需要同时考虑模型外形、安装方向、可用空间、相互避让以及整体质量分布。SatLayoutOpt 将这些输入组织成连续流程：导入卫星模型，设置安装信息与安全包络，配置安装筒、基座、分段整流罩和装载条件，再搜索满足约束的候选布局。选定方案后，可以继续人工微调并保存独立版本。

项目支持侧挂与顶部安装，以及由下锥段、圆柱段、上锥段组合的轴对称整流罩。原始 STEP 文件保留为精确几何源；三维查看使用按需生成的浏览网格，布局与校核使用保存的正式安全包络和安装信息。

## 主要功能

| 功能 | 内容 |
| --- | --- |
| 模型上传 | 导入 `.stp` / `.step` 模型，查看三维外形与几何信息。 |
| 卫星设置 | 配置单位、比例、质量、质心、安装面、向上方向及各方向安全间隙，生成安全包络并固化模型记录。 |
| 前置配置 | 设置装载数量、安装筒半径与高度范围、基座、分段整流罩和质心偏移限制；支持固定放置、环向对称、镜像及硬／软约束。 |
| 布局优化 | 根据空间、碰撞、遮挡、安装关系和水平质心偏移等约束搜索候选布局；支持方案筛选、历史项目查看及 Excel 安装参数导出。 |
| 人工微调 | 在许可范围内调整卫星位置、角度、悬高和安装筒尺寸，支持组合与拆解、位置交换、锁定、撤销重做、实时校核及微调版本保存。 |
| 数据管理 | 检索和查看已固化的模型记录，预览正式包络、下载包络 STL，并支持单条或批量删除记录。 |
| 硬件设置 | 按功能模块设置 CPU、并发、内存、缓存及三维显示参数，支持资源推荐方案，保存后重启生效。 |

人工微调提供三维、俯视、正视、侧视和四视图，支持放大查看及独立控制卫星、名称和辅助标记的显示。连续调整时校核最新布局，正式校核通过后才能保存。

典型流程：**上传 STEP 模型 → 完成卫星设置与包络生成 → 固化模型 → 配置装载与安装约束 → 运行布局优化 → 比较方案 → 按需人工微调 → 保存与导出**。

## 技术组成

- 前端：React、React Router、Vite、Three.js，负责页面交互与三维预览；优先使用 WebGPU，条件不满足时回退 WebGL。
- 业务后端：Rust、Axum，负责 HTTP 接口、数据存储、后台任务及计算资源调度。
- 几何与数值计算：Python、CadQuery / OpenCascade、NumPy / SciPy、OR-Tools 等，负责 STEP 处理、安全包络和布局求解；搜索结合约束规划、连续调整与自适应大邻域搜索（ALNS）。
- 桌面：Tauri、WebView2，负责原生窗口、本地服务及进程生命周期。
- 数据与配置：SQLite 保存模型元数据；模型、派生产物与历史结果保存在本地 `data/` 目录。前后端及工具链参数统一维护在 `config/sat_layout_opt.toml`。

## 本地运行

源码启动面向 Windows 10 / 11 x64。准备 Python 3.12 的 Conda 环境、Node.js / npm，以及项目环境内的 Rust / Cargo、MSVC C++ 构建工具和 Windows SDK；桌面运行还需要 WebView2 Runtime。

默认 Conda 环境为 `D:\Conda_envs\payload-opt`。先核对 `config/sat_layout_opt.toml` 中的 `packaging.python_environment`、`packaging.conda_executable` 及 `desktop.tauri` 下的工具链路径；环境位置不同时，在此统一修改。仅安装 Python 与前端依赖还不足以构建 Rust 和桌面程序。

在 Conda 可用的终端中，从项目根目录安装依赖：

```powershell
conda run -p D:\Conda_envs\payload-opt python -m pip install -r requirements.txt
conda run -p D:\Conda_envs\payload-opt npm --prefix frontend ci
```

依赖和工具链就绪后，双击根目录的 `start-desktop.bat`，或在 PowerShell 中执行：

```powershell
.\start-desktop.bat
```

入口会读取统一配置，构建所需的 Rust 程序与前端资源，再启动桌面窗口。首次构建耗时较长，后续启动复用有效缓存；构建或启动失败时，当前命令窗口会保留错误信息。

GitHub 源码以桌面启动入口及其必要依赖为分发范围，开发测试、内部文档和安装包构建脚本不随此仓库发布。模型及历史方案按配置保存到本地数据目录。

## 当前边界

布局优化结合约束求解与启发式搜索，不保证全局最优；在有限搜索预算内没有找到候选，也不等于数学上无解。空间、碰撞及遮挡判断依据正式安全包络和项目约束，复杂凹形结构可能受到保守几何近似的限制。

当前已纳入安装筒、基座和分段整流罩的空间约束。整体质心按已配置卫星的质量与质心计算，不包含安装筒、基座和整流罩等结构的质量；项目也不提供结构强度、动力学或实际装拆路径的工程验证。结果用于方案探索与比较，最终方案仍需工程复核。
